# TEAM: сотрудники без почты (логин + пароль) и пакетные приглашения

Дата: 2026-11-21. Релиз: 3.10 (вместе с сайтом и сервером).

## Зачем
Сейчас сотрудник TEAM существует только через почту (приглашение на email → регистрация/вход → принятие). У части команд у людей нет рабочей почты. Владелец хочет создавать сотрудникам логин и пароль сам, и делать это пачкой. Приглашать по почте тоже нужно пачкой. Владелец считает привязку почты правильным путём: интерфейс объясняет почему и оставляет явную кнопку «всё равно создать без почты».

## Что решили (слова владельца)
- Логин и пароль создаёт владелец (или администратор), по одному и пачкой.
- Перед созданием без почты объясняем, почему почта лучше. Кнопка «Всё равно создать без почты» остаётся.
- Приглашения по почте тоже пачкой.
- Всё выкладывается вместе (приложение, сайт, сервер), без проблем на каждом шаге.

## Не цели
- Публичная регистрация по логину (регистрация остаётся только по почте или через OAuth).
- Смена логина после создания.
- Вход по логину в мобильном приложении как отдельная доработка (сервер его принимает, поле там принимает любой текст; подпись «Email» не меняем в этом релизе).

## Модель данных
Одно аддитивное поле: `User.login String? @unique` (строчные буквы).

Аккаунт без почты хранит служебный адрес `<login>@login.centrio.invalid`. Так `User.email` (обязательное и уникальное) остаётся заполненным, а весь существующий код продолжает работать. Адрес не маршрутизируется никем (`.invalid`), письма на него режутся в `sendEmail` до отправки (рядом с существующей защитой для `tg_<id>@centrio.me`).

Признак «аккаунт только с логином» = `email` оканчивается на `@login.centrio.invalid`. Когда сотрудник привязывает настоящую почту, `email` заменяется настоящей, а `login` остаётся: вход по логину продолжает работать.

Логин: 3–32 символа `a–z 0–9 . _ -`, начинается с буквы или цифры, хранится строчными, глобально уникален. Отличить от почты просто: в логине нет `@`.

## Серверные точки
Новый модуль `lib/login-accounts.js` (чистая логика, покрыта тестами): нормализация и проверка логина, транслитерация имени в логин, генератор пароля (без похожих символов, `crypto.randomInt`), служебный адрес, `isLoginOnlyEmail`, разбор списка почт.

`routes/org-accounts.js` (подключается из `org.js`):
- `POST /:orgId/accounts/prepare` {names[], role} → строки {name, login, password}. Записи не создаёт. Логины подбираются так, чтобы не совпасть ни с чем в базе и друг с другом (суффикс 2, 3, …). До 30 строк.
- `POST /:orgId/accounts` {accounts:[{name, login, password?, role}]} → {created[], failed[]}. Создаёт аккаунты, делает их ACTIVE-участниками. Места проверяются внутри транзакции под блокировкой строки организации (`FOR UPDATE`): параллельные запросы не обойдут лимит. Что не поместилось или не прошло, получает свою ошибку, остальное создаётся. Пароль возвращается в ответе один раз; в базе только bcrypt, в журнале пароля нет.
- `POST /:orgId/members/:userId/reset-password` {password?} → новый пароль один раз. Только для аккаунта, у которого ещё нет настоящей почты и который активный участник этой команды. Администратор может это только у сотрудников. Все сессии аккаунта закрываются.
- `POST /:orgId/invites/batch` {emails[], role} → результат по каждому адресу: sent / invalid / duplicate / already_member / already_invited / no_seats / failed. До 30 адресов.
- Удаление участника без настоящей почты: сессии закрываются, аккаунт отключается (`isActive=false`), логин остаётся занятым. Об этом диалог предупреждает.

`routes/auth.js`:
- `/login`: поле `email` без `@` ищется как логин. Для логинов блокировка 10 неудач / 15 мин на логин (от перебора паролей), сообщение «Неверный логин или пароль». Лимит по IP для `/login` поднят до 120 за 15 минут: офис за одним адресом, где все входят утром.
- `/me` и ответ входа добавляют `login` и `loginOnly`.
- `/forgot-password`: для логина ничего не отправляется (ответ общий).
- `POST /auth/email/attach/start` {email} и `/confirm` {code}: сотрудник с аккаунтом только с логином привязывает настоящую почту по коду из письма. Адрес не должен принадлежать другому аккаунту. После этого работает «Забыли пароль» и вход по почте.
- Список участников (`GET /:orgId/members`) возвращает `login`, `loginOnly`, а в `email` для таких людей отдаёт логин.

Счётчики и реклама: аккаунты, созданные владельцем, не должны попадать в «регистрации» для рекламы (офлайн-конверсии Метрики) и не создавать «новую регистрацию» в админ-пуше. Создаются без пробного периода и без приветственного письма.

## Интерфейс
Сайт, страница «Команда» → вкладка «Участники»: блок «Добавить сотрудников» с двумя режимами:
1. «Пригласить по почте» (по умолчанию, рекомендуем): поле для нескольких адресов (через новую строку, запятую или пробел), роль, результат построчно.
2. «Создать логин и пароль»: сначала карточка «Почта нужна не для формальности» с причинами и двумя кнопками: «Пригласить по почте» и «Всё равно создать без почты». После согласия: вставить имена (по одному на строку) → «Подготовить» → таблица с логинами и паролями, которые можно править → «Создать N аккаунтов» → экран с выданными данными: копировать у каждого, «Скопировать всё», «Скачать CSV», предупреждение «пароли показываются один раз».
В списке участников у аккаунтов без почты метка «без почты» и действие «Сбросить пароль». Журнал действий знает новые события (`member.create_login`, `member.password_reset`, `member.invite_batch`).

Приложение:
- Поле входа: «Email или логин». «Забыли пароль», когда введён логин: объяснение, что пароль сбрасывает руководитель команды.
- Профиль: у аккаунта без почты показывается логин и блок «Привяжите почту» (почему, поле, код, подтверждение). Там же смена пароля (уже есть в сайте, в приложении используем существующий `PUT /api/user/password`).

Сайт: страница входа принимает логин.

## Риски и как закрыты
- Утечка пароля: возвращается один раз по TLS, не пишется в журнал, не хранится открытым.
- Перебор: блокировка по логину.
- Захват чужого аккаунта владельцем: сброс разрешён только для аккаунта без настоящей почты и участника команды. Привязал почту: аккаунт его.
- Письма на служебный адрес: режутся в `sendEmail`.
- Гонка за места: блокировка строки организации.
- Дубли логина: уникальный индекс + подбор + повторная проверка при создании.
- Долгое хеширование: пачка не больше 30, хеширование асинхронное и последовательное.
- Откат: колонка аддитивная; серверные файлы копируются в `.bak-*`.
